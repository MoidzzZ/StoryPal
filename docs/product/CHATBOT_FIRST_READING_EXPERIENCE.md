# StoryPal 初次阅读陪读体验设计

**目标：** 让从未读过《流浪地球》的用户愿意开始、愿意继续，并在每次停下来时都有一个自然的对话入口。所有内容严格受已读边界约束。

## 产品判断

当前的 `Notes` 适合保存“请记住我的长期偏好”这一类显式、稳定信息，例如偏好的讨论方式、希望少追问、希望保留猜测。它不应承担阅读过程本身：

- 它不会自动区分“作品事实”“我的猜测”“当时的感受”；
- 它不该因一次感叹就写入，且目前不会形成可回看的阅读脉络；
- 若把剧情记录与用户偏好混在一起，Dream、长期人格和故事证据会互相污染。

因此，`Notes` 保持小而克制；后续新增独立的**阅读手账**，只在用户明确要求记录、或确认某条阅读事件时写入。

## 第一次打开《流浪地球》

不应出现长问卷，也不应预告故事走向。建议的首屏只提供三个低压力入口：

1. **从第一段开始陪我读**：StoryPal 用一两句不超出开篇的信息说明“我们只走到你读过的地方”，邀请用户读完一小段回来聊。
2. **我已经读到这里**：用户用章节、段落、进度条或“刚读完某段”定位；系统更新已读边界，而不是要求理解整套内部 order。
3. **先告诉我它值得读吗**：只给不剧透的阅读气质与现实议题入口，例如规模感、普通人视角与艰难选择；不承诺“后面会怎样”。

第一轮对话的成功标准不是解释设定，而是让用户产生一个属于自己的问题：*“如果必须带着整个地球离开，人会先失去什么？”*

## 一次自然陪读的循环

```text
读一小段 → 用户带着反应回来 → StoryPal 回应/澄清 → 留下可选问题或猜测 → 用户继续读
```

每个节点只做一件事：

| 用户时刻 | StoryPal 应做的事 | 不应做的事 |
| --- | --- | --- |
| “我刚开始读” | 确认无剧透规则，给一个轻量进入点 | 概述全书或介绍人物关系网 |
| “这里看不懂” | 先用已读证据解释术语、事件或上下文 | 用后文证明现在的疑问 |
| “这个人为什么这么做” | 区分原文事实、合理推断与尚未揭晓 | 把猜测说成答案 |
| “我有点难受/震撼” | 接住感受，追问一个可选的具体点 | 强迫分析或强行检索 |
| “我猜会不会……” | 帮用户把猜测写清楚，可选记录 | 暗示猜对或猜错 |
| “我隔了几天忘了” | 只回顾已读范围、以用户上次锚点为中心 | 重新讲述未读部分 |

## 阅读手账：下一项真正值得做的能力

阅读手账与 `Notes` 分库、分权限、分来源。第一版只需三种条目：

- **反应**：用户主动留下的感受或想圈出的句子；
- **问题**：尚未解开的疑惑，记录提出时的阅读边界；
- **预测**：用户明确说“我猜……”，记录原话、当时边界与可选置信度。

关键规则：

- 只在用户确认“记下它”或明确发出记录意图时写入；
- 每条都保留作品、会话、时间、阅读边界和来源类型；
- 回看时首先展示用户自己的原话；StoryPal 只能补充当前边界内的证据；
- “验证预测”不是自动剧透按钮。只有用户已读进度足够且主动请求核验，才比较已读证据；不足时只说“我们还没读到能回答它的地方”。

这比泛化 Notes 更能制造继续阅读的动力：用户不是在完成任务，而是在和未来的自己约定一个问题。

## 应优先实现的功能顺序

1. **阅读定位友好化**：把内部 `max_seen_order` 包装成章节/段落进度选择，保留当前锚点；这是所有防剧透体验的入口。
2. **已读范围短回顾**：根据锚点与证据生成 3–5 句回顾，明确“只到这里”。
3. **阅读手账 v1**：反应、问题、预测的显式记录与回看，不自动推断。
4. **预测核验**：仅依据当前已读边界回答“现在能不能验证”。
5. **10 条真实 Luna 轨迹**：先验证“困惑澄清、情绪陪伴、猜测、回归复习、越界问题”等体验，再决定是否加工作流。
6. **HistoryMemory**：只在阅读手账与会话摘要形成真实需求后加入；它用于找回“我之前怎么想的”，不替代故事证据。

## 暂不做

- 自动生成章节测验、读后感模板或打卡压力；
- 自动替用户保存情绪、性格或“偏好”推断；
- 根据未读内容制造悬念、推荐下一章节或暗示预测对错；
- 用 RRF、reranker 或复杂多 Agent 掩盖尚未验证的对话体验问题。

## 首轮验收场景

以未读过《流浪地球》的用户为对象，至少验证：

1. 能在不理解内部 order 的情况下设定“我读到哪”；
2. 读完一小段后，能得到一段严格已读范围内的解释或共鸣；
3. 用户留下的猜测能在数日后被原样找回；
4. 面对“后面会不会……”时，系统不暗示答案，且仍能让用户愿意继续读；
5. 用户暂停后回来，能迅速重新进入自己的阅读脉络。
