# M3 情景记忆：实现契约与当前状态

更新：2026-10-03。M3-A 存储／来源／水位已实现，13 项隔离测试通过；自动抽取、归档触发、语义索引和聊天工具尚未接入，不宣称 WebUI 已能跨会话回忆。

## 1. 它记什么，不记什么

记录有情境、有互动过程且对后续讨论有帮助的经历，例如“喜欢角色的救人选择，但质疑转折铺垫；经过讨论澄清，质疑的是叙事呈现而非动机能否成立；前文铺垫仍待核验”。不能为了凑变化而把澄清写成先前误读。

- Note 保存当前有效的剧情外交互约定，不改为经历仓库。
- 手账保存用户明确要求记录的感受／问题／预测，不因经历抽取自动双写。
- checkpoint 是同一会话的工作交接；日经历是可按需回取的跨会话材料，不自动全量注入。
- 工具原始 Observation 留在会话／trace；只有影响理解的查证结论、未解问题可进入经历，失败不升级为核实。工具日志不单独长期建库。
- 用户观点和 AI 假说不是故事事实，经历也不能放宽阅读进度。`MEMORY.md` 按用户决定仍暂缓。

## 2. 当前已实现：M3-A 事实源

实现：`chatbot/src/storypal_chatbot/episodic_memory.py`，类 `EpisodicMemoryStore`。它不调用 LLM，不注册工具，不读正式会话或维护其他记忆。

本地路径：`.storypal/episodic_memory/<owner_hash>/memory/YYYY-MM-DD.md`；采用用户目录隔离，文件按来源开始时刻的上海日期分组，跨午夜保留起止时间。原始 nanobot 无时区消息按当前应用上海时区解释；缺失／无效时间或仅有日期时拒绝，不补造精确时刻。

每项正文包含标题、发生时间、讨论情境、理解变化、未解问题、会话与消息序号。MD 内的 `episode-meta` 注释保存稳定 ID、源 session_key、原消息序号／时间／短摘录、归档范围、owner、作品及保守已读边界。注释是溯源元数据，不是独立 JSON 记忆事实源；后续索引读取可读正文，人工修改正文不会被旧副本覆盖。

接口：

| 方法 | 输入 | 输出／约束 |
| --- | --- | --- |
| bind_session | owner、session、当前 archived 水位 | 首次从当前水位开始，不静默回扫历史；已有绑定不允许换用户 |
| processed | owner、session | 已提交处理水位；损坏或用户不匹配报错 |
| commit_archive | 原消息、本批归档末尾、最多 4 个抽取候选；可选服务端作品／已读边界 | written／processed／ids；水位相同返回 duplicate，不重写 |
| list_records | owner | 从该用户 Markdown 恢复正文及来源；这是读取，不是检索 |

每个候选包含 title、context、development、open_question，以及 1～8 个 `{message_index, quote}` 原消息引用。至少一个引用来自用户；摘录必须逐字出自本批已归档消息、最多 200 字，可信运行时附加块先剥离。可引用助手／工具以追溯讨论过程，但来源匹配不证明摘要内容或工具结论语义正确。

全部候选验证后才写日文件。每个文件原子替换，全部成功后推进水位；若中途失败，水位不变，重试用批次／槽位稳定 ID 防重复。多日文件不是一个跨文件事务，当前假设同一会话由一个维护者写入；不承诺并发事务或防篡改。原始会话不删除。

作品／边界由调用侧提供，忽略模型候选里的同名字段。**存储层不能验证传入 archived_end 确为上游已提交水位，也不能验证 caller 给出的阅读范围**；M3-B 必须从 SessionStore／已保存运行时来源取得并校验，不能信模型或当前新作品。多作品／边界不明批次应拆分或跳过剧情经历，不能存为无 scope 的可自动注入剧情记忆。

## 3. 下一个实施包：M3-B 压缩触发抽取

- 观察已提交 checkpoint 水位，处理新归档的稳定用户／助手讨论；不每轮抽取，不静默扫描启用前的旧历史。
- 明确原始消息 source_id、时间、工具结果状态，防止把失败／空结果总结成查证成功。先小批限制输入，未处理部分保留水位继续处理。
- 设计与现有 Note 抽取的协调：尽量复用一次归档维护请求，或明确独立低频请求成本；不得把剧情混入 Note，也不为了合并而改变其来源验证。
- 输出经历候选后共用 M3-A admission；格式／来源失败不推进，空候选可推进。后台异步执行，不阻塞回复。
- 先替身 provider／临时 SessionManager 验证整条链，真实抽取效果与额度另行授权核验。本轮没有新增模型请求。

## 4. 再后续：M3-C 回忆接线

用现有 BGE-M3 编码 query，LanceDB 作可重建索引；一次候选召回、单一相似度阈值和独立 Token 预算。先完成一个回忆工具，不另加复杂 Gate、时间路由或多轮搜索。算法会话负责可比实验，应用侧不等待新模型／排序胜出。

必须保持 owner、作品和已读范围安全；进度回退后不能借经历暴露未来内容。没有可用索引／无命中时明确区分，不假装已搜索全部原始历史。少量自动注入是否值得，待跨会话用例验证，不预先全量注入。

## 5. 当前核验与用户参与

13/13 程序测试，0.21s，使用合成讨论；首次 10 项包含于最终 13 项，不重复累加。覆盖跨午夜分组、重建实例、用户绑定／隔离、不写其他记忆、未归档／编造引用／工具独占／时间缺失拒绝、全部验证后写、失败重试与重复水位、空候选、运行时材料剥离、模型 scope 忽略及读取正文。

尚未验证：模型是否抽出真正有价值的经历、自然语言回忆是否命中、聊天是否自然接续。现在不要求用户在 WebUI 测这个模块。可体验后只需核验“新会话记得我们为什么改变理解，且没有篡改过去的观点”，不是要求用户检查 MD 或填工程测试表。
