# M3 情景记忆：实现契约与当前状态

更新：2026-10-03。M3-A 存储已实现；M3-B 联合低频抽取／归档观察已接入并部署，相关程序回归 70/70。真实抽取语义未核验，M3-C 语义索引与聊天回忆工具尚未完成，不宣称 WebUI 已能跨会话回忆。

## 1. 它记什么，不记什么

记录有情境、有互动过程且对后续讨论有帮助的经历，例如“喜欢角色的救人选择，但质疑转折铺垫；经过讨论澄清，质疑的是叙事呈现而非动机能否成立；前文铺垫仍待核验”。不能为了凑变化而把澄清写成先前误读。

- Note 保存当前有效的剧情外交互约定，不改为经历仓库。
- 手账保存用户明确要求记录的感受／问题／预测，不因经历抽取自动双写。
- checkpoint 是同一会话的工作交接；日经历是可按需回取的跨会话材料，不自动全量注入。
- 工具原始 Observation 留在会话／trace；只有影响理解的查证结论、未解问题可进入经历，失败不升级为核实。工具日志不单独长期建库。
- 用户观点和 AI 假说不是故事事实，经历也不能放宽阅读进度。`MEMORY.md` 按用户决定仍暂缓。

## 2. 当前已实现：M3-A 事实源

实现：`chatbot/src/storypal_chatbot/episodic_memory.py`，类 `EpisodicMemoryStore`。它不调用 LLM，不注册工具，不读正式会话或维护其他记忆。

本地路径：`.storypal/episodic_memory/<owner_hash>/memory/YYYY-MM-DD.md`；采用用户目录隔离，文件按来源开始时刻的上海日期分组，跨午夜保留起止时间。原始 nanobot 无时区消息按当前应用上海时区解释；缺失／无效时间或仅有日期时拒绝，不补造精确时刻。

每项正文包含标题、发生时间、讨论情境、理解变化、未解问题、会话与消息序号。MD 内的 `episode-meta` 注释保存稳定 ID、源 session_key、原消息序号／时间／短摘录、归档范围、owner、作品及保守已读边界。注释是溯源元数据，不是独立 JSON 记忆事实源；后续索引读取可读正文，人工修改正文不会被旧副本覆盖。

接口：

| 方法 | 输入 | 输出／约束 |
| --- | --- | --- |
| bind_session | owner、session、当前 archived 水位 | 首次从当前水位开始，不静默回扫历史；已有绑定不允许换用户 |
| processed | owner、session | 已提交处理水位；损坏或用户不匹配报错 |
| commit_archive | 原消息、本批归档末尾、最多 4 个抽取候选；可选服务端作品／已读边界 | written／processed／ids；水位相同返回 duplicate，不重写 |
| list_records | owner | 从该用户 Markdown 恢复正文及来源；这是读取，不是检索 |
| bound_sessions | owner | 只枚举已经绑定该用户的来源，用于新会话继续维护旧归档，不扫描认领全部旧历史 |

每个候选包含 title、context、development、open_question，以及 1～8 个 `{message_index, quote}` 原消息引用。至少一个引用来自用户；摘录必须逐字出自本批已归档消息、最多 200 字，可信运行时附加块先剥离。可引用助手／工具以追溯讨论过程，但来源匹配不证明摘要内容或工具结论语义正确。

全部候选验证后才写日文件。每个文件原子替换，全部成功后推进水位；若中途失败，水位不变，重试用批次／槽位稳定 ID 防重复。多日文件不是一个跨文件事务，当前假设同一会话由一个维护者写入；不承诺并发事务或防篡改。原始会话不删除。

作品／边界由调用侧提供，忽略模型候选里的同名字段。**存储层不能验证传入 archived_end 确为上游已提交水位，也不能验证 caller 给出的阅读范围**；M3-B 必须从 SessionStore／已保存运行时来源取得并校验，不能信模型或当前新作品。多作品／边界不明批次应拆分或跳过剧情经历，不能存为无 scope 的可自动注入剧情记忆。

## 3. 当前已实现：M3-B 联合低频维护

实现 `archive_maintenance.py` 的 ArchivedMemoryCoordinator，复用 record_interaction_note 唯一运行时入口；工具名／数量不变。旧 ArchivedNoteCoordinator 保留兼容测试，但运行入口不再同时调用它。ToolContext 提供的真实 sessions namespace 被用于读已提交 JSONL，避免读错默认会话目录。

触发时机是**压缩提交后的下一次用户请求**，不是归档函数内部回调，也不是每轮抽取：初次绑定以当前水位为起点；之后当前会话有新归档则处理一批，否则可处理同一 owner 先前已绑定的旧会话。新开会话后也能触发旧归档维护。无用户输入时不主动轮询，因此关闭应用后不会即时抽取；原始 JSONL／checkpoint 仍保留。

每次观察最多一个异步批次；输入最多 24 条非空文本消息、12000 字消息正文，每条最多 1500 字，标明截断。JSON／提示词包装另占 tokens，该限制不是 provider 总预算。剩余归档在下一次观察处理，不在一次请求里循环追赶所有历史；无用户来源批次不调用模型。

一份维护调用返回独立 note_ops／episodes 两组候选，各最多四条：Note 只引用用户原话，通过原有 apply_candidate 入库；经历可引用用户、助手和工具，但至少有用户来源，共用 EpisodicMemoryStore admission。两类全部预验证后，先保存 Note 再写经历／联合水位；失败保留水位重试，Note 正文去重、经历稳定批次 ID 去重。不是跨文件事务。底层 provider 沿用既有 retry 策略，不保证一次维护只发一个网络请求；也未实测合并后的 token／延迟收益。

工具状态区分 error、empty、evidence_returned、unclassified。evidence_returned 只表示返回符合来源 scope 的证据，不能证明文学解释已经成立；失败／空／未分类结果不能归档成核实。截断材料不支持补全未知结论。

阅读 scope 来自验证过的已保存运行时后缀，并只接受来源为 storypal_session_state 的可识别块，不解析用户伪造文字或其他故事视图中的同名字段。换作品分批，取同作品批次的保守上界；段落前缀所在单元也计入上界，供后续回忆工具防止回退进度时泄露未来。**范围不明时仍可维护合法 Note，但首版不写经历**；非剧情泛聊的无作品经历、旧混合后缀的范围恢复暂列 TODO，不把它们存成可无条件注入的剧情记忆。

新联合维护启用时不补扫启用前旧归档，既有 Note 文件／原始会话不删除；旧独立 Note 的待处理水位不迁移或补跑。此取舍避免重新认领旧来源，旧待提取候选不保证在此版本自动追回。

开关：进程环境 STORYPAL_AUTO_NOTE 和 STORYPAL_AUTO_EPISODE 默认均开启；可独立关闭对应类别。两者全关闭时暂停维护而不推进水位；重新开启可能处理暂停期间的待归档内容，不等于遗忘或删除。自动抽取不修改显式手账、USER／SOUL、MEMORY.md 或故事数据。

本阶段仅用替身 provider／临时 SessionStore 验证，无新增真实模型请求、无真实用户数据输入。服务已加载新入口，但首次真实有价值抽取与最终回忆效果另验。

## 4. 当前已实现：M3-C 回忆接线

新增 `episodic_recall.py` 和 `RecallInteractionHistoryTool`，插件／白名单／常驻 Skill 已接线。工具唯一模型参数为 `query`（1—240 字），owner、作品和完整已读边界来自当前服务端状态，不能由模型指定。当前白名单为12项，旧 `search_memory` 只兼容既有显式 SQLite 记忆，不机械多查。

流程：读取当前 owner 的日 Markdown → 校验来源、时间、范围和正文 ID → 当前作品索引 → LanceDB cosine 查询时预过滤 `ord <= max_seen_order` → 取最多30候选 → 单阈值 → 按独立预算整项填充 → 返回正文、时间、原话、归档范围及匿名会话引用。返回 ID／范围再次与当前 Markdown 对照，残留缓存或损坏来源不得提供他人／未来材料。无合法记录时不加载模型或搜旧缓存。

索引位于用户私有目录 `.storypal/episodic_memory/<owner_hash>/index/<work_hash>/`。时间和来源哈希不进入向量编码，编码标题／讨论情境／理解变化／未解问题；返回仍保留完整溯源。源内容／元数据哈希、模型路径／配置哈希及索引格式决定重建；重启后可复用未变索引。索引可覆盖同用户同作品的较晚经历，但预过滤和最终校验共同防止回退泄露。本版用 LanceDB 小规模精确向量查询，未创建 ANN；每次仍读该 owner 日文件并计算源哈希，没有宣称海量性能优化。模型权重原地替换但 config 不变的自动检测暂未覆盖，固定官方模型不应这样替换。

默认 `T_auto=0.55`（cosine similarity，不是概率）、独立预算1000估算 tokens，无固定2条上限。预算按完整返回 UTF-8 JSON 字节数 / 3 向上取整，包含正文、原话和诊断；超限整项舍弃，不截去来源。不是 provider tokenizer 的严格预算。候选池30条意味着不保证召回所有过阈值的经历。

运维可在启动进程前设置 `STORYPAL_EPISODE_MODEL`（默认本机 `D:/models/BAAI/bge-m3`）、`STORYPAL_EPISODE_THRESHOLD` 和 `STORYPAL_EPISODE_TOKEN_BUDGET`，再重启 gateway。缺少模型／依赖返回工具错误，不伪装为没有历史；只从本地加载，不自动联网下载。相同模型在经历模块进程内共用延迟加载实例，执行移入工作线程；首次加载仍可能较慢，没有宣称与 StoryMem 内部实例共用或实现全面并发取消。可选依赖 `pip install -e './chatbot[episodic]'`；本机复用已有 LanceDB 0.38.0、sentence-transformers 5.7.0，不升级环境。

输出 `status=ok|empty`、`reason=matched|no_eligible_episodes|below_threshold|token_budget`、`episodes`、阈值／预算诊断；匹配时有 `source_version`。依赖、源损坏或索引范围不一致返回 `ToolResult.error`。无命中不能推出从未讨论，来源校验也不证明语义正确。主 Agent 自行决定是否使用及消解指代，无独立 Gate／改写模型、自动全量注入、时间路由或多轮搜索。

必须保持 owner、作品和已读范围安全；进度回退后不能借经历暴露未来内容。没有可用索引／无命中时明确区分，不假装已搜索全部原始历史。少量自动注入是否值得，待跨会话用例验证，不预先全量注入。

本地官方 BGE-M3 实际加载，1024维，经历实例复用成立。2条隔离合成经历、3个本地查询，无 provider／真实用户请求。去掉记账字段后的诊断阈值为-1，用于观察分数（不是生产阈值）：含糊原问的目标0.461312、干扰项0.461487；人工明确讨论对象后的目标0.761106、干扰项0.464917；无关问最高0.351885。默认0.55可阻挡后两种干扰，但仍会漏掉含糊原问。人工查询不是实际 Agent 改写，不从此小样声称阈值已校准／召回准确率提升。该进程首次26.229s（包括载模建索引），后两查询0.132／0.047s；先前完整 Markdown 编码原型首查53.847s，两进程状态不同不能归因成提速。

仍未验证：真实联合抽取是否有价值、Agent 是否自然消解指代并选对记忆源、长聊跨会话是否接续。下一包优先一条经独立授权的隔离“抽取→新会话回忆”体验和真实 query 只读导出；不为测试强制修改正式用户进度或回扫旧会话。用户方便时核验观点归属、澄清是否变成虚构误读、未查证是否仍保持未知。
