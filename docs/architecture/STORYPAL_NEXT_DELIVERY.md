## 1. 先交付可体验的 Agent

复用 nanobot 的 Agent Loop、结构化工具调用、会话 JSONL、Checkpoint、WebUI 和 Luna-only 配置。StoryPal 本轮补四个业务闭环：

1. 用户级阅读进度：按 `owner_id + work_id` 持久化，重启与新会话恢复。用户明确报告且位置唯一时写入；从问题推测的位置只用于自然询问，确认后才写。服务端始终用已确认进度限制故事证据。
2. Note 与阅读手账：Note 保存当前有效的非剧情交互约定、纠正、偏好、临时项和开放观察，每轮注入；显式与自动 Note 都调用同一抽取器。手账独立保存作品感受、问题和预测。明确写入同步完成；自动 Note 在压缩边界处理。
3. 互动经历记忆：仅在 Checkpoint 压缩边界从稳定对话中抽取有场景、变化和后续意义的事件，写入 `memory/YYYY-MM-DD.md`，保存时间和原消息引用。它回答“我们当时发生了什么、为什么改变做法”；当前规则留在 Note。Markdown 是事实源，BGE-M3/LanceDB 是可重建索引。
4. 按需回忆：主 Agent 自行决定是否调用一次 `recall_interaction_history(query)`；工具用 BGE-M3 编码 query，按 owner 硬过滤，在 LanceDB 取固定候选池，以单一相似度阈值筛掉弱相关项，再按独立 Token 预算顺序填充。空结果明确返回。时间过滤、MMR、二次改写、多轮搜索和独立 Gate 暂缓。

两个 Skill 规划为：“首次阅读陪伴”负责陪聊与工具选择建议，“剧情事实核验”负责证据优先和防剧透。确定性 Workflow 首先做更新进度、记录手账、压缩后 Note／经历维护；旧预测检查在进度变化后异步执行。首版沿用固定工具白名单与必要的写入确认；ToolSpec 元数据和动态工具组等待真实工具误选或权限规则重复再补。

### Agent 框架只补业务薄层

nanobot 已提供 Agent Loop、模型结构化工具调用、会话历史与压缩、WebUI；StoryPal 不重新实现框架。当前代码使用固定工具白名单，关闭命令与文件执行工具；各业务工具在服务层执行已读边界和 owner 隔离。首版只补三项可以直接验收的薄层能力：写操作的对话确认与持久状态、统一的业务错误返回（缺少阅读进度、证据越界、存储失败等不能伪装成空检索）、以及在已有 trace 中保留工具名、参数、耗时、结果状态和证据引用。无需沙箱、动态工具注册或工作流框架迁移。若日后工具误选显著，才实验按阶段暴露工具组。

## 2. 简单的记忆检索接受规则

构造中文真实回忆问题和难负例，人工标记 episode 是否足以支撑回答；观察 BGE-M3 cosine 分布，选择偏向精确率的单一阈值 `T_recall`。每次记录原问题、Agent query、候选分数、接受结果、注入 token 与最终回答。样例不足以分开正负例时，不宣称阈值已校准，保守返回空结果并继续收集样例。

首版只需 `T_recall` 与 `memory_token_budget`。固定内部搜索深度，返回条数由预算决定。owner 是必需硬隔离；涉及作品剧情的 episode 在写入时拒绝未读事实，读取时不得扩大当前已读边界。

## 3. 后续检索算法实验

当前 StoryMemory 共有 108 个 StoryUnit，LanceDB 查询使用 cosine，代码没有建立 ANN 索引，可作为精确搜索基线。互动经历初期也使用精确搜索。数据增长后，比较精确扫描和 LanceDB 的 IVF_PQ、IVF_HNSW_SQ：记录 P50/P95、吞吐、索引大小与构建耗时，ANN Recall@K 以精确结果为参照，并检查 owner／阅读边界过滤后的效果。只有规模与延迟证明收益才切换在线索引。扩容或合成数据只用于性能实验，不能冒充真实业务相关性。

实验顺序：

1. 真实 Agent Query：固定用户原话、可见上下文、Luna tool-call query 和 gold evidence，对比原话、Agent 改写、人工改写上限。
2. 稀疏与融合：同一中文金标比较现有二元词 FTS5/BM25、jieba 词项和 BGE-M3；保留已有 RRF 负向结果，只针对坏例重试 Hybrid。
3. Embedding：同一语料、切分、金标比较 BGE-M3 与候选中文／多语模型，报告 Hit@K、MRR/nDCG、模型和索引大小、编码及查询耗时。
4. Reranker：固定 Dense/Hybrid 候选池比较无重排、Qwen3-Reranker-0.6B 与 BGE reranker；分开报告候选召回和重排后的排序、端到端延迟。
5. 按失败类型试进阶 RAG：指代消解、渐进式单元重复、跨单元因果分别尝试 Query Rewrite、父子证据回取、结构化状态辅助；每项独立消融，有净收益才进入在线路径。

所有实验都用已读范围硬过滤，金标贴近中文首次阅读对话。对外区分检索上限实验与真实 Agent 端到端轨迹。

## 4. 交付顺序

| 顺序 | 产物 | 用户可核验结果 |
| --- | --- | --- |
| M1 | 用户级进度、确认、手账写读、两个 Skill | 新会话继续阅读，能记录／回看预测，无未读证据 |
| M2 | Note.md、统一 Note 抽取、每轮注入 | 明确纠正立即生效；压缩后仍记得交互约定 |
| M3 | 按日互动经历、单次回忆工具、阈值与预算 | 隔天能说清一次共同经历和来源；弱相关记忆不进入回答 |
| R1 | 固定评测集与精确检索基线 | 可复跑的质量、延迟和安全数据卡 |
| R2 | ANN、Embedding、Reranker、失败类型消融 | 每项方案的收益、成本、坏例和上线决定 |

每阶段运行相关回归，并向用户说明下一步、预期结果及需核验的体验。数据抽查可按此前约定交由 Luna，正式指标仍以可复跑脚本为准。
