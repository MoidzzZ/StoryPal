# StoryPal 检索算法实验计划

更新：2026-10-03（Asia/Shanghai）。本目录只承载独立算法线，不改应用检索默认配置。

## 目标与范围

以《流浪地球》首批 9 例验证：用户要形成何种理解、当前可见上下文缺什么、该取哪个已读来源，以及检索是否补齐必要证据。案例见 [scenarios.json](scenarios.json)。R12、R14、R20、R25、R26、R21、R29 复用只读主金标；P01 为结构历史导航探索例；N01 为不应检索的决策负例。P01 的必要证据是实验假设，文学解释仍待 GPT-6 Luna 小范围只读核验；模拟用户不能独自裁定金标。

## 实验阶梯

1. **采集与回放**：分开记录 `raw_user`、人工 `gold_rewrite`、真实工具参数 `agent_query`。现有材料没有真实 Agent query。使用 `retrieval_experiments/replay.py capture` 接收人工挑选的工具事件；不扫描真实聊天、不调用模型。未检索是合法决策，按案例单独核验。
2. **稀疏路径**：复跑当前 bigram OR 实际路径，逐例标出 FTS5 与 Python 扫描回退；在隔离索引中做 jieba 索引端/查询端一致的 OR、AND、短语对照。首批与既有 29 例的两种 query 来源均已完成；精简词项组合留待具体坏例驱动。
3. **候选与排序**：同一 query、已读边界、Top K、证据预算下比较 FTS5、BGE-M3 与离线 RRF。已补固定的真 jieba OR＋Dense 等权／2:1 RRF 和实际装包回放；两种融合仍未改善原话装包联合覆盖。后续仅在可用且获准的专用 reranker 条件下另做排序实验；不同候选池或回退路径单列，不归因于单一算法。
4. **解释性评审**：按证据充分、纠错正确、指代消歧、跨段因果和已读边界评最终回答；这一项需要单独授权的模型样本与人工复核，不能由召回指标替代。

## 统一记录

- 固定 `work_id=wandering_earth`、各例 `max_order`、来源版本、query 来源、候选数、Top K、首次模型加载与预热耗时。
- 有金标案例报告 Hit/Recall@3/5、MRR、必要证据联合命中、无关结果数；空金标与 N01 不进排序分母。
- 检查每条候选的 `work_id/order`，逐例记录误召回、零结果、别名失配、扫描回退；R21/R29 必须零越界。空结果只表示当前已读范围未知。
- 本地原文与真实用户轨迹不进入公开仓库；只提交代码、人工问题、单元编号与不含原文的汇总。临时结果保存在 `.runtime/retrieval-experiments/`。

## 暂缓与交接

第二 Embedding、父子组织、ANN 暂缓。生产应用若要提供真实查询，请增加一个受控的只读导出：案例关联 ID、故事 ID、服务端确认的 max_order、是否调用工具、实际 `search_story` 参数、顺序与匿名 trace_ref；不要把金标或人工改写注入 Agent。应用线负责接入，算法线仅接收隔离样本。新增真实模型调用或原文外发前另报样本与预算并等授权。
