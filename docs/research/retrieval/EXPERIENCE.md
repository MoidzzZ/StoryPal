# 可讲述的检索优化经历

更新：2026-10-04。本记录从StoryPal的连续陪读需求展开，区分已完成实验、开发样本观察和后续计划。

## 1. 需求：让连续共读有可靠的理解依据

StoryPal陪用户逐步读小说，需要承接当前阅读片段、阅读进度、用户手账和过去的讨论。用户可能问“他为什么改变立场”，也可能问“我上次的猜测现在还成立吗”。系统既要取回相关的已读原文，也要区分读者旧观点和故事事实；暂时找不到证据时应说尚未查清，不能据此断言作品没有交代，更不能拿未读情节补答案。

应用线负责连续阅读、进度、手账修订与旧观点回看；我的算法线研究取得哪些来源、如何排序和选择证据，以及有限上下文能否支撑理解。应用回看候选仅提示值得检查，不自动等于预测被证实或证伪。

实验针对这些检索任务：事实与流程定位、指代消歧、跨阶段原因、人物立场与关系变化、历史过程回顾、读者记忆纠错、旧预测复核、已读边界下的未知，以及用户暂停时不检索。它们需要的来源和验收分母不同，不能只算关键词命中率。

## 2. 失败：找到相关段落，仍可能缺少完整依据

我先复用同作品29个开发案例，27个有非空必要证据集合，其中5个需要两个单元。逐层查看候选池、Top3/Top5和模型实际收到的装包材料，并核对来源版本和阅读边界。

代表性坏例R25问“早期光柱为何倾斜、启航时为何变直”。向量候选池已找到早晚两段，Top5也完整，但默认装包只取3条主证据及最多1条直接相邻补充，早段落在第五位且不相邻，因此被丢弃。瓶颈是排序与选择，单纯增加召回不会自动补齐依据。

另一类问题出现在来源本身：自动摘要、结构历史可能与对应原文不一致，甚至把分隔线单元当事件。它们只能作导航线索，最终要核验原文。历史回顾命中首末两段，也不保证中间过程完整。

## 3. 假设与对照：拆开查询、召回、排序和装包

我分开记录用户原话、人工答案词改写、Sol模拟问法和Luna真实工具query；人工上界不冒充真实Agent。稀疏检索还拆开严格FTS与实际FTS→扫描回退，避免把不同路径混成一个算法结果。

先比较jieba OR与BGE-M3，再以固定RRF等权和Dense:Sparse=2:1融合。各路最多Top10、最终Top5，装包使用应用原有2400估算token预算。融合会执行两路，不把相同返回数量说成计算成本相同。

然后对全部开发例做自动双问题分句，比较RRF与同候选的两路首位保留。再用已有缓存交叉比较完整问题词项、明确给定上文与3种打包规则；这轮只重排固定候选，不声称新query已经重新做向量检索。

真实模型批次按用户指定使用GPT-6 Sol模拟读者、GPT-6 Luna运行陪读及范围查验。六个隔离场景复用主进程人格、阅读边界、故事工具、向量服务和packer；原文外发获得明确授权。物理请求持久计数，禁用重试和后台模型工作，输出token只是目标而非服务端硬上限，参数差异如实记录。

## 4. 结果：保留负结果，不用单段指标替代理解完整性

| 对照 | 已完成结果 | 判断 |
|---|---|---|
| 原话Dense | 候选联合27/27，Top5联合27/27，实际装包26/27 | 召回充足仍可在装包丢跨段证据 |
| 真jieba＋Dense固定融合 | 两种融合装包仍26/27；等权MRR低于Dense，2:1追平 | 没有整体覆盖收益 |
| 自动双问题分句／首位保留 | 装包26/27降至25/27，新增R28损失，R25未解决 | 不采用该规则 |
| 缓存词项语境与3种打包 | 原话各组仍26/27；MRR 0.895升至最高0.938，重排Top5联合却降一例 | 首段提前不等于证据集完整 |
| 授权真实query小批 | 5条首次query、1次无工具暂停；3个既有非空金标装包3/3 | 开发样本观察，尚非独立算法收益 |

六场景共18/24次物理请求（Sol 6、Luna 12，含一次独立范围查验）；provider报告输入103278、输出2561、合计105839 tokens。Sol问法的三个计分案例装包2/3，实际Luna query为3/3：R25早段从第四升第三，进入主证据。不过query和可见Agent语境同时变化，不能将差异全部归于一种改写算法；也没有成对最终回答盲评。

边界例没有返回未读单元，暂停例真实不调用工具。P01回顾虽命中暂定首末证据，仍缺中间单元；额外Luna查验也有内部矛盾与阵营归属错误，因此保持待核验，不升格金标或并入分母。

## 5. 采纳与拒绝：交付可复现诊断，保持生产默认

我交付了分层指标、同源缓存回放、实际工具回执审计、物理请求账本、正负实验记录和版本哈希，未修改主金标、正式索引或应用默认Dense检索。早期固定融合、朴素分句和缓存词项选择未达到新增覆盖要求。扩展包的RRF Top5正文词项互补后来出现正信号，但同样要保留相对Dense的损失和更大候选池的退化，不能因为一个坏例改善或MRR变好就上线。

当前51项定向测试覆盖冻结契约、来源与边界、输入不泄漏结论、分组和候选池约束。测试证明这些约束得到检查，不证明文学解释全部正确。没有线上收益、真实用户提升或跨作品泛化的结论。

## 6. 从开发坏例扩大到理解任务

为了避免继续围绕R25堆规则，我在新检索评分前固定15个理解任务、每任务两种问法，共30问、9个事件组。14个任务有原文支持的必要证据候选，31处原文位置和哈希完成核验；1个任务特意缺少读者旧记忆。旧预测fixture是合成输入，不能当真实读者记录。正式独立语义金标仍为0，必要性和两问等价性待独立复核。

同任务及同事件家族必须同组，不能把改写算独立样本。作者已经接触同作品开发材料，本集只能叫拟留出候选，不能声称严格未见盲测；修正契约须保留旧版和理由，不能根据未来算法结果改标。

四路协议随后在CPU扩展包中执行：Dense、真实jieba／FTS、固定融合和确定性结构历史辅助，另对预选5任务做同候选专用Qwen重排。评分前只修订H04-a的错误时间前提，旧版保留；所有必要候选与分组未按结果变更。新30问、旧29开发例及26行阶段检查分开，独立数据复核仍未完成。

新故事候选分母28问，Dense实际装包16/28，固定融合18/28；融合新增5问成功又损失3问，任务双问均完整仍5/14，所以净增加不能代表问法稳定性提升。结构路线只有5/28，揭示名称选择和历史来源不足；这次是真实执行的确定性离线路由，但仍不是真实Agent导航。部分选中材料的正文仅是分隔线，或摘要与原文不一致，已标风险，没有修改索引去适配成绩。

完全离线加载的Qwen3-Reranker-0.6B，在相同Dense Top10和装包规则下，把5任务10问装包6/10提升为9/10，新增三个成功、无新增损失。剩下一問的必要材料不在候选池，重排无能为力。这是排序值得继续验证的正信号，但标签provisional、样本只有预选五任务，且100对CPU评分165.70秒、每问中位15.92秒，尚不能接在线主路。

26个阶段行中14个完整集合未读到，不纳入通常覆盖分母；所有路线返回材料零越界，但没有生成回答，不能宣称模型正确表达未知。H15缺读者记忆和暂停N01只验固定离线不检索夹具，旧预测的手账／经历取得及最终理解未完成。

本轮没有远程provider请求、CUDA、下载、外发原文或真实聊天读取。第一次Dense在报告保存时因资源统计依赖缺失失败，改用系统接口重跑，记录总114次CPU编码和重复成本。40项定向测试通过。生产仍保持Dense默认；下一步先独立复核数据，再扩大固定同池Qwen验证与最终回答比较，核对已有开发负例、成本和不同作品。模拟用户Sol、数据核验及角色Luna的约定保留，旧模型预算未用槽位不再消耗。

## 7. 扩展到30业务任务：定位漏损并检验固定选择规则

我进一步冻结30个业务目标、60个本地表达和16个事件组，分别为23故事查证、4读者记忆、3无需故事检索。记忆类检查修订状态、归属和过去查证失败；决策类检查暂停、倾听约定和当前材料已足够。它们的夹具来源是合成记录，尚未做真实工具／Agent验证；新故事问法也尚未召回，不把30任务写成30项通过。

在已有14故事任务28问和29开发案例的固定排名上，我先拆开池外缺失、Top5截断和实际装包丢弃，再固定五个规则：原packer、原文去重、分隔线过滤加去重、邻接优先、正文新增词项覆盖。六路线各用Top5／Top10单列，共60组；最多4条和2400估算tokens保持一致，没有查看必要集合来选择材料。这轮没有token预算丢弃或选中正文重复，因此去重／扩大token不是得到支持的失败原因。

RRF Top5词项互补相对同RRF默认，材料完整从18/28到20/28，双问都完整的任务从5/14到7/14；旧开发从26/27到27/27。它终于保留了R25早晚两段，且没有增加最终条数，但相对Dense仍损失H12-b与H13-b；Top10用同规则还降到15/28。正文-only稀疏索引也从混合字段的6/10降至5/10。正信号与反例一起说明：候选更多、邻接更强或词覆盖更高，并不保证理解依据更完整。

最终无模型审计约18.74秒，峰值111.0MiB；Top5词项选择约6ms仅是缓存选择开销，不能当线上端到端延迟。第一次内存FTS表命名冲突失败，修正实现后保留失败和完整复现，再为峰值统计复现一次；15480次重复装包计算和60次FTS查询不算新样本。51项程序测试通过，正式原文、金标、默认配置未改。

我已准备57问570对的完整模型／query／document／prompt SHA绑定队列，旧100对缺完整权重证明不追认新缓存。600次／1200秒持久预算、CPU两线程、分包落盘与资源窗口守卫完成，新评分仍0；用户正在验收WebUI，重模型加载等待资源窗口释放。新增数据独立核验、最终回答成对比较和跨作品验证仍未完成。下一步要用这些门槛判断是否值得应用接入，当前只交付算法探索结果。

## 两分钟讲述稿

我在StoryPal小说陪读项目里负责检索算法探索。业务要求是连续共读：既要理解当前情节，又要回看人物变化和读者旧预测，而且只能使用已读证据。我先区分问题缺的是故事原文、读者旧观点，还是根本无需检索，再把候选召回、排序和模型实际收到的证据分开评估。

我复用29个开发案例，发现一个跨阶段问题的早晚两段都已召回，早段却因为排名靠后且不相邻被装包丢弃。稀疏路径又经常退回扫描，所以我拆开严格FTS和回退，固定jieba与向量融合、分句和语境选择对照。早期融合没有新增覆盖，分句反而从26/27降到25/27；首段排名提高也没补齐证据集合，这些负结果都保留了。

随后在授权预算内用GPT-6 Sol模拟读者、GPT-6 Luna实际陪读，六个场景共18次请求，取得五条真实query和一次无工具暂停。三个有既有金标的实际query取齐了证据，但query和Agent语境同时变化，我没有宣称独立算法收益。历史回顾的模型核验仍有矛盾，保持待核验状态。

为了扩大业务覆盖，我冻结了30个任务、60种表达、16个事件组，分开故事、记忆和不检索任务。已有14故事任务上，固定RRF Top5加正文词项互补，完整装包从18/28到20/28，旧开发26/27到27/27；但相对Dense仍有两个坏例，Top10同规则还退化。同池Qwen重排的先行十问从6/10到9/10，每问CPU中位约16秒，因此只能作为扩验信号。

现在我交付了任务版本、分层漏损、正负结果、成本和可恢复评分队列，尚未改生产默认。后续要独立复核必要证据，再做完整同池重排和成对回答验收。这个经历是从找到相关段落，推进到完整、可追溯、符合阅读边界的理解依据；材料齐备还要经过回答验收，才能谈业务收益。
