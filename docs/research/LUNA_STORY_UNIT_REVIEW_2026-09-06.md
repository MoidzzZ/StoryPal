# Luna：StoryMemory 单元产品审阅（2026-09-06）

审阅模型：GPT-5.6 Luna。审阅材料为完整抽取元数据、代表性单元、字段统计与向量/FTS 边界验证；要求不向首次读者透露后段剧情。

以下判断只针对“从未读过《流浪地球》的用户进行无剧透陪读”的产品价值，不涉及全书简介，也不展开样本中后段内容。

先说明证据范围：

- 已由抽取报告证实：共有 108 个顺序单元；抽取无降级，错误文件为空；向量检索和 FTS5 在一个早期查询上命中相同核心单元；设置 `max_order=2` 时，向量结果只返回 1、2 号单元。
- 仅由代表性样本显示、尚未代表全库证实：字段之间的类型一致性、摘要是否普遍存在因果压缩、人物/地点/术语的标注完整率，以及所有查询下的防剧透可靠性。

A. 最值得支持的 3 个陪读场景

1. 当前已读范围内的“即时解释与定位”

产品价值最高。用户刚开始阅读时，常见需求不是知道后文，而是确认：

- 这个术语在当前段落是什么意思；
- 某个行动为什么发生；
- 当前有哪些已明确的背景条件；
- 前文提到的对象、人物或地点在哪里出现过。

现有单元具备顺序、章节、原文行号、摘要和检索字段，适合支持“只解释我已经读到的内容”。尤其是 `max_seen_order` 能把解释范围变成硬边界，而不是依赖模型自觉。

建议交互形态：

- “用目前读到的内容解释一下”
- “这句话和前面哪一段有关？”
- “只根据我读过的部分，帮我理清因果”

已由样本证实：早期内容可以被向量和 FTS5 检索到，且顺序边界至少在 `max_order=2` 的示例中生效。  
仍需人工验证：跨章节指代、相邻单元边界、FTS5 降级时是否同样严格遵守边界。

2. 阅读中的反应陪伴与问题承接

这类数据能让 StoryPal 不只是“问答机器人”，而是围绕用户刚刚读完的单元回应：

- 接住震撼、困惑、压迫感或好奇心；
- 把用户的问题绑定到当前锚点；
- 区分“文本已经说明”“可以合理推断”“目前还不知道”。

这也是阅读手账最直接的使用入口：用户可以留下一个反应或问题，下一次回来时从原来的阅读位置继续，而不必重新复述上下文。

已由样本证实：单元有顺序和原文行号，具备把对话锚定到文本位置的基础。  
仍需人工验证：用户反应是否应绑定到单元、段落还是章节；同一个问题跨多个单元时如何聚合；手账恢复是否会造成不必要的剧情提示。

3. “预测—暂存—回读后核验”的无剧透陪读

首次阅读时，用户经常会提出“我猜接下来会怎样”。产品可以支持：

- 只记录用户自己的预测；
- 不确认对错；
- 在用户主动读到更后面并再次询问时，基于新的阅读边界进行核验；
- 在此之前只讨论预测依据，不调用未读内容。

这比主动抛出悬念更适合无剧透陪读，也能形成长期阅读参与感。

已由样本证实：单元有稳定顺序，可作为预测记录的时间锚点。  
仍需人工验证：用户跨越多少阅读进度后才适合允许“核验”；核验时是否需要用户明确提出，而不能由系统主动提醒；模型是否会从预测内容反向猜测并泄露后文。

B. 字段使用分级

1. 可直接展示给用户

在满足当前阅读边界的前提下：

- 当前章节名：适合用于位置提示，但不应主动展示未读章节列表。
- 当前单元的原文片段：可作为引用依据，必须只取 `order <= max_seen_order` 的内容。
- 当前已读进度：例如“已读到第 N 个阅读单元”，但不要展示总单元数作为进度诱因。
- 用户自己的手账内容：反应、问题、预测可以原样展示和编辑。
- 经模型重新组织的“当前范围内解释”：不能直接把数据库摘要原样暴露，应由边界过滤后的证据生成。

有条件可展示：

- 人物、地点、术语标签：仅限已经出现在用户已读范围内，并经过类型和名称清洗；更适合作为当前段落的辅助标签，而不是全局人物表或全书索引。

2. 只能作为模型内部检索线索

- `unit_id`
- `order`
- 原文行号
- 向量嵌入
- LanceDB 检索结果及分数
- FTS5 索引字段
- 未经审查的 `summary`
- 原始 `characters`、`locations`、`key_terms`
- 章节到单元的内部映射
- 召回数量、排序分数、降级状态

特别是摘要不能直接作为“安全的用户可见摘要”。摘要虽然短，但可能把多个段落的因果关系、冲突和结论压缩在一起，导致用户提前获得超出当前语境的信息。

3. 需要先清洗或规范化

- 实体类型：样本中 `characters` 出现了明显不像人物的内容，说明事件、阵营或概念可能被混入人物字段。
- 地点层级：大陆、国家、城市、空间区域等粒度可能不一致，需要统一命名和层级。
- 术语别名：同一对象可能有简称、全称或不同译写，需要建立规范名与别名映射。
- 空数组：`characters=[]`、`locations=[]`、`key_terms=[]` 不能直接解释为“文本中没有相关实体”，也可能是抽取遗漏。
- 摘要边界：需要标记摘要覆盖的起止单元，并禁止摘要跨越用户未读边界。
- 原文行号：需验证是否稳定、是否能准确回指原文，避免引用错段。
- 章节字段：需统一章节名称、篇章层级和排序规则。
- 单元切分：需要检查一个单元是否包含多个事件、对话转折或跨段落信息。

C. 质量风险与对话风险

1. 已由样本直接显示的质量风险

- 字段类型污染：人物字段包含非人物概念，说明实体分类不可直接用于展示或人物关系图。
- 早期单元存在空字段：不能判断是文本确实没有实体，还是抽取器漏标。
- 摘要信息密度较高：单元摘要可能同时包含背景、因果、争论和结果，存在超出用户当前阅读需要的风险。
- 章节和单元顺序是防剧透的关键基础：一旦排序、边界或过滤出现偏差，检索质量问题会直接变成剧透问题。

2. 由系统设计可推断、但仍需测试的风险

- 向量检索可能召回语义相关但顺序较后的单元；必须先过滤再排序，不能只在结果返回后凭模型判断。
- FTS5 与向量检索的结果可能不一致；降级路径也必须执行同一 `max_seen_order` 条件。
- 相邻单元补充召回容易越过边界，尤其是边界单元本身不完整时。
- 摘要中的跨句因果关系可能让模型“顺手补全”未读信息。
- 用户问“后面会不会……”或“我猜对了吗”时，检索器可能被误用为探查未来的工具。
- 没有 `active_work` 和 `max_seen_order` 的有效状态时，系统可能错误地沿用旧作品或旧进度。
- 预测记录若被当作事实，模型可能在回应中把用户猜测说成文本结论。
- Notes 与阅读手账混用，会造成用户未明确同意的长期记忆写入，或把一次性阅读反应永久化。

3. 对话层面的核心原则

每次回答都应明确区分：

- 原文当前已明确说了什么；
- 根据当前范围可以合理推断什么；
- 当前范围还没有证据说明什么。

D. 阅读手账 v1：最小字段设计

建议先做“用户明确确认后保存”的极简结构：

- `entry_id`：手账条目 ID
- `active_work`：作品标识
- `anchor_order`：用户记录时的阅读锚点
- `entry_type`：`reaction` / `question` / `prediction`
- `content`：用户确认保存的原文内容
- `created_at`：创建时间
- `status`：`open` / `resolved`，默认 `open`
- `resolved_at`：可选；仅在用户主动核验或确认问题已解决时填写

v1 不必保存：

- 模型对用户性格的推断；
- 自动生成的情绪标签；
- 未经确认的模型总结；
- 全书章节映射；
- 自动预测结果；
- 与未读单元的关联。

严格防剧透规则：

“任何手账读取、检索、展示、问题核验和模型生成，都必须同时限定在当前 `active_work` 且 `order <= max_seen_order` 的证据范围内；预测条目在用户主动推进并明确请求核验之前，一律不得与未读内容比对、不得提示可能正确或错误、不得触发未来检索。”

这条规则应实现为数据层过滤和测试断言，而不是只写在提示词中。

E. 接下来两周的最小开发顺序

1. 固化阅读边界契约

明确 `active_work`、`current_anchor`、`max_seen_order` 的缺省行为；没有有效边界时禁止剧情检索。为向量、FTS5 和相邻单元补充路径统一加入硬过滤。

2. 建立防剧透检索测试集

至少覆盖：

- 早期事实查询；
- `max_order=2` 边界；
- 向量与 FTS5 降级；
- 跨章节查询；
- 模糊的“后来”“接下来”提问；
- 边界前后相邻单元；
- 空结果和状态缺失。

当前已有早期查询和 `max_order=2` 示例，但还不足以证明全路径安全，需人工复核测试结果。

3. 做字段规范化与来源标记

先处理实体类型、别名、空字段语义、章节排序和原文回指；每个可用事实保留 `unit_id/order/line_range` 来源。未清洗字段只进入内部检索，不进入用户界面。

4. 实现阅读手账 v1

只支持三种条目：反应、问题、预测；提供“确认保存”动作；默认绑定当前阅读锚点；不与 Notes 自动互写。实现按作品和阅读边界读取的过滤逻辑。

5. 做首次阅读对话验收与人工红队

用几组典型流程验收：

- 用户只读到开头并要求解释；
- 用户表达困惑或情绪；
- 用户提出预测；
- 用户问“后面会不会”；
- 用户从旧锚点回来继续阅读；
- 向量不可用切换 FTS5。

验收标准不是“回答得像不像”，而是：不能出现未读证据、不能把预测说成事实、不能把抽取摘要原样当作安全展示内容。
