# 连续记忆与陪读行为：2026-10-04真实合成小样

用户明确批准最多12次GPT-6 Luna＋3次GPT-6 Sol；实际15次，全部stop，失败／重发0。各步骤单次，传输之前写入账本，不借旧批次余量。执行脚本`chatbot_tests/manual_memory_acceptance.py`；原始合成材料只在忽略目录`.runtime/isolated/continuous-memory-20261004-approved15/`。

## 1. 做了什么

六场景使用独立workspace／owner／会话和仓库公开人格模板。发送材料只有人工合成的阿岚小故事、合成讨论、手账及规则，无《流浪地球》原文、真实聊天／Notes／身份资料。正式进度和开关不变，无Embedding模型／GPU加载，回忆工具用真实LanceDB＋确定性向量隔离模型决策。

压缩用真实Consolidator闲置压缩入口，保留18条原消息及8条近期回放，重要讨论退出现行原文窗口；**不是手动设置last_archived**。但测试显式调用压缩入口和归档观察，不是让正式WebUI自然聊到token阈值，不宣称闲置计时／上下文压力自动调度完整验收。

### 观察到的理解贡献

- C1摘要、抽取与最终回答都保留“喜欢救人，但关心转折铺垫”，没有编造用户认为角色不该救人。抽取保留检索失败与未知，经历附m2／m6用户原话；不把来源失败变成“作品没有铺垫”。
- Note只保存“讨论转折先区分动机和铺垫”，实际分类constraint，与“以后”约定相符；角色感想没串写Note，原手账未变。
- C2主Agent仅凭摘要＋近期闲聊接回关注点，没有再查记忆。两份摘要表述不同，但都保留澄清与未核实；不按固定标题数量判文学语义。
- C4确实走了失败工具返回，不是提前把错误直接写给模型让它重复；最终没有捏造原句。当前答复仍沿用用户给出的s-12，内部ID的人类可读性另验。
- C5取到了真实保存的合成旧预测，回复“目前片段不支持原判断”，不事后改旧观点。这里是前台手账对照，**不是异步JournalRecheck**，正式后台复核仍关闭。
- C3与C6有get_story_evidence可选却没有调用，证明本批没有把全部需求强行检索；C3轻量表达理解，不输出长分析。语气是否真的像共读伙伴仍由真人判断。

## 3. 局限与下一步

这是一套合成角色素材的六种行为，不是六本作品、成规模文学准确率或真实用户满意度。旧会话由人工构造，原文取证失败为模拟；C1只有一条可回忆经历且向量确定性，不验证Embedding难负例／阈值／ANN。所有工具只开放各场景必要的只读工具，所以“没改手账”有快照证据，但不能外推为在开放写工具时模型始终正确判断权限。

尚缺：多段真实已读视图与结构历史参与的理解、更多人物／因果问题、自然连续会话中重复澄清或含糊指代、跨日多经历互相竞争、完整删除／记忆过期，以及用户体验。继续采用固定行为目标、同来源条件和独立预算，不用无限重试换好样本。

本批主要补上“原生压缩提交→联合维护→重启读取→模型主动回忆”的证据链。下一轮优先让已读StoryMem视图、用户讨论和工具证据共同参与，而不是只扩大对阿岚这一个夹具的改写。
