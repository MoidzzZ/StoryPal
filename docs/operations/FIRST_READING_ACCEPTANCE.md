# StoryPal 首次阅读行为验收规范（桌面网页首版）

> 2026-09-24 建立。目的：用少量、可重复的真实用户行为验证“边读边聊”，把程序契约、模型表现和读者体验分开记录。本规范不包含小说原文，也不把模拟测试冒充真人验收。

## 范围与执行约束

- 本轮只覆盖桌面宽度（至少 1024 px）、单作品首次阅读、阅读进度、预测手账、非剧情 Note；手机端、多作品和按日情景记忆不在当前验收范围。
- 自动化使用临时用户和合成段落，不改真实用户的阅读进度、Note 或手账。服务端只做健康与未认证接口检查，不打印原文、令牌或本地配置。
- 模拟读者场景由 **GPT-5.6 Terra** 设计和审阅；它不得替代真实读者判断，也不调用 Luna 生成答案。测试尽量只运行受影响文件，避免重复跑全量回归。
- 每个场景记录：执行日期、输入意图、操作或调用、预期、实际、证据、判定（通过／失败／待真人核验）。不允许仅凭代码存在就宣称端到端通过。
- 安全硬条件：未确认的阅读位置不得推进；故事证据不得超过用户已确认边界；跨用户不能读到进度、手账或 Note；工具输出不能伪装成用户记忆。任一违反即阻断验收。

## 七个最小用户场景

| ID | 用户行为与操作步骤 | 预期结果 | 自动化证据 | 仍需真人／真实模型核验 |
| --- | --- | --- | --- | --- |
| R1 打开阅读器 | 在桌面聊天页点击“阅读原文” | 左侧显示本作品章节、原文及行号；未登录者不能直接调取原文接口 | `test_reader.py`；本地接口未认证状态码 | 入口是否好找，双栏排版和加载感受 |
| R2 定位与续读 | 选章节、滚动、调字号，再关闭或刷新页面 | 章节跳转；字号和位置在浏览器本地恢复；滚动不推进已读边界 | `story-reader-pane.test.tsx` 覆盖滚动不报告章末；代码检查保存键 | 实际跳转、续读位置和阅读舒适度；本轮自动测试未覆盖全部 UI 操作 |
| R3 划选提问 | 在已读段落划选短句，输入“这里为什么这样做？”并带入聊天 | 发送选文、章节、行号与问题；回答仍受已确认边界约束 | 阅读器实现可定位到选区拼装；`test_story_memory.py` 覆盖服务端边界 | 真实选区操作和 Luna 是否理解指代、给出恰当证据 |
| R4 读完一章 | 点击“我已读完本章”，再确认或取消 | 点击仅发起报告；确认后持久更新且不可倒退，取消不写；滚动不等于确认 | `story-reader-pane.test.tsx`、`test_story_memory.py`、`test_tools.py` | 对话确认措辞是否自然，真实聊天是否正确执行 |
| R5 困惑澄清 | 只读完开篇时，问一处设定、动机或因果 | 只引用已读证据；证据不足时说明不确定，不用未来剧情证明 | `test_story_memory.py` 的边界与证据测试 | 真实答案的可读性、事实正确性和零剧透 |
| R6 记录预测 | 明确要求“把这个猜测记下来”，换会话请求找回 | 即使未确认进度也可保存无锚点预测；按用户、作品和边界隔离，跨会话可回看 | `test_tools.py` 的无锚点预测和跨会话手账测试 | Agent 是否稳定选对写入／读取工具，回看语气是否自然 |
| R7 记住互动约定 | 明确说“以后先聊感受，再给证据”，换会话验证，再要求忘记 | 非剧情约定进 `Note.md` 并每轮注入；忘记后不再使用；工具文本不误写 | `test_interaction_note.py`、`test_note_consolidation.py` | 自然对话中是否误把一时情绪或引用内容写成长期偏好 |

## 执行批次与通过条件

1. **程序契约（每次相关改动）**：运行上述 Python 定向文件和两个网页组件文件；任何失败按场景定位，不用其他通过项抵消。测试使用项目内临时目录。
2. **本地服务冒烟（每次交付）**：`/health`、首页应可达；未认证的 `/api/webui/storypal-reader` 应返回 401。成功返回 200 只证明可达，不证明真实聊天成功。
3. **真实模型小样（功能稳定后）**：最多五个独立对话场景，优先 R3–R7，每场景控制在两轮左右；保存工具选择、确认／取消、证据来源和最后回答的脱敏记录。不自动扩大用户进度。
4. **读者体验（用户方便时）**：R1–R4 在实际桌面浏览器走一遍，重点判断可发现性、阅读舒适度、续读与打断感；不要求为了测试把未读章标为已读。

程序契约通过只可记为“自动化通过”。基础陪读体验要称为“验收通过”，还需实际网页操作无阻塞、真实 Luna 场景零剧透／零次未确认推进，且至少一次跨会话找回手账和遵守 Note。没有执行的项目明确写“待核验”。
