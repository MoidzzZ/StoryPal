# 第一阶段真人验收指南

更新：2026-10-04（Asia/Shanghai）。本指南是当前真人入口；更早的首次阅读、口吻和手账验收文档保留作历史专项，不代表所有后来功能已获真人认可。

## 1. 验收目标与范围

目标不是证明“能调用工具”，而是判断：StoryPal 能否跟着真实阅读位置和读者的想法，持续提供有依据、有理解增量、不越界的共读帮助。

第一阶段范围：桌面网页阅读器、定位与确认进度、已读故事视图、按需原文／结构检索、连续讨论、显式手账、非剧情 Note，以及已实现的压缩／跨会话记忆链路。阅读体验与模型语义必须真人核验；压缩触发、隔离、工具故障和存储恢复主要由开发侧验证。

不以“同意读者”作为通过条件，也不设唯一文学解读。一个不同的解读，只要回应了问题、讲清依据和局限，也可以有价值。不得为了得到满意答案让模型给作者补写动机。

建议分两次完成：第一次20～30分钟，优先 A、B 和 C1；完整功能核验再补15～20分钟。没有进行的项目记“待核验”，不用为了凑测试反复聊天。

## 2. 准备与安全约定

2. 使用桌面浏览器。确认当前模型为 GPT-6 Luna；本次不要来回切换模型，否则体验差异难定位。
3. 保持同一浏览器及本机身份，使用普通“新会话”验证跨会话；不要清除浏览器存储、换隐私窗口或重置阅读进度。
4. 选择《流浪地球》中自己确实读过、愿意讨论的段落。不要标记未读章节，不查阅未来单元或全书人物命运。

## 3. A：阅读器、定位和进度（约5～8分钟）

### A1 打开、选文、续读

- 点“阅读原文”，停在已经读过的段落；调字号、滚动、关闭再打开或刷新。
- 划选一小段，用阅读器提供的带入聊天功能提出自己的问题。
- 预期：能看清原文、按钮不重叠，选文确实进入问题；阅读位置／字号能恢复，聊天不会被阅读器操作丢失。
- 安全要求：滚动、选中或刷新不等于确认已读，不能自动推进防剧透边界。
- 记录：哪个操作做不了、选文是否丢失、刷新后是否异常。阅读器可以浏览原文，但回答的已读权限仍由已确认进度决定；不要为了测试自己浏览未读内容。

### A2 段尾标记、取消和确认

先选择自己实际已经读到的段尾，点“读到这里”。

第一轮看到定位／确认请求后回复：

> 先取消这次进度更新，保持原来已确认的位置。

预期：取消不写入新位置。若该段已确认且界面提示无需重复更新，不强求出现新的确认流程。

确实需要推进到这个已读位置时，再点同一段尾；核对位置正确后，在下一轮回复：

> 对，我已经读到这里，确认更新阅读进度。

预期：只在下一轮明确确认后保存；刷新／普通新会话仍能恢复同一身份的进度。不要为测试倒退或跳到未读位置。若没有新已读位置，这部分的“实际推进”可以待下次真实阅读再核验。

注意：段落可能落在 StoryUnit 中间；系统只开放已确认行之前的原文，不应因此开放整单元的结构快照。已确认位置在阅读器中的高亮暂未实现，不以缺高亮判本轮失败。

### A3 用印象定位，不完整复述

> 我好像读到了【自己记得的事件／人物动作】，不是原句，你先帮我找一下大概位置，别直接更新进度。

预期：结合有辨识度的印象给候选或问一个必要的澄清问题；不能因为找到某段就擅自确认。候选可能不唯一，不承诺任意模糊描述都能精确定位；但不能一律要求你完整复述原文。

如果你只记得“有人说了一句话”，请逐步补一个真实线索，不要提供内部单元ID帮助模型作弊。定位结果不应附带候选之后的剧情解释。

## 4. B：核心陪读质量（约15～20分钟，优先完成）

以下不要求全部另开会话。一条讨论可以顺带覆盖多项；模型不必每轮调用检索，不能仅凭没有工具调用就判失败。

### B1 第一回复是否抓住点

带入已读短段后表达真实感受，例如：

> 我挺在意【人物】这里的反应。让我觉得【自己的感受】的不是结果，而是【具体动作／对话】。你怎么看？先别给我复述情节。

预期：先接住具体关注点，再给一个有依据的理解区分，例如立场与关系、角色动机与作者铺垫、人物知道的与读者知道的。不要泛泛说“这个人物很复杂”，也不要照原文换词复述。

关键评价：去掉你的原话后，它还贡献了什么？一个恰当的解释、比较、反例或暂时保留的分歧即可，不要求每次长篇分析。

### B2 连续纠正与观点承接（最重要）

在 B1 后继续，按真实意图纠正它。例如：

> 你刚才偏向解释他为什么这样做了。我更在意的是作者有没有把这个转变写自然，别急着替作品圆。

再下一轮：

> 那结合刚才两轮，你觉得我现在真正纠结的是什么？哪些有文本依据，哪些仍只是我们的解释？

预期：正确承接你的修正，不把“质疑铺垫”偷换成“认为人物不可能这样做”；区分你的观点、作品事实和AI解释；不把你没说过的话写成你先前犯的错误。

失败例：只说“你说得对”后重复上一轮；继续为作品补动机；每轮重新从头解释，丢掉讨论方向。

### B3 跨段人物、因果与伏笔（只选一个真实问题）

选择两处你实际已读且愿意联系起来的内容：

> 前面【已读事件A】和刚才【已读事件B】，你觉得是在推进同一个人物／问题吗？有哪些对应，又有哪些地方还不能连起来？

预期：不只讲当前状态；需要时利用已读结构历史和原文证据，说明联系是否成立。若来源不齐，指出缺的是哪类信息，而不是编造完整因果链。

检验点：有没有真正比较两处，能否提出至少一个有根据的联系或差异；没有充分依据时能否保留未知。没有明显伏笔就不要强行寻找“作者早有安排”。

### B4 查证和解释的边界

对刚才一项具体断言追问：

> 你说【具体断言】，这是原文明确交代，还是你的推断？如果是明确交代，帮我回看我已读部分的依据；找不到就说还没核实。

预期：引用／定位可在你已读原文中核对；能够撤回或降低不可靠断言。检索失败只证明这次未找到，不证明作者没写；摘要或结构标签不能冒充逐字原文。

不要要求每句话都附来源。用户可先观察答复和可见工具记录，实际工具参数、返回边界和落盘由开发侧核对；“我已查询”这句自然语言本身不是工具执行证据。

### B5 情绪暂停与发散

当你确实想停下来时：

> 先不分析了，我想缓一缓，别再追问剧情。

预期：停止分析，不为了回看预测或补齐证据继续调用故事工具；简短接住即可，不机械总结、不逼你给结论。

可选再聊一个与阅读有关但非剧情事实的问题：

> 我发现自己会更在意人物关系，而不是宏大设定，你觉得这种读法会错过什么吗？先随便聊聊，不用记成长期偏好。

预期：允许发散，能有交流而不是立刻拉回剧情检索；不把这句话自动确立成长期偏好。低频记忆抽取的实际分类由开发侧另验，不要求你观察隐藏存储。

### B6 防剧透（贯穿，不强求主动索要结局）

可用：

> 只按我现在已确认读过的部分说：关于【目前的疑问】能判断到哪一步？后面的结果不要告诉我，也别暗示猜测对不对。

预期：不能用未来内容证明当前判断，不能说“以后你会发现你猜对了”。观点可以讨论，未来事实不能透露。若你发现越界，立即停止相关追问，告诉开发侧哪句泄漏；不用自己去读未来内容验证。

## 5. C：用户记忆与跨会话（第二次可补，约10～15分钟）

### C1 显式阅读手账：保存与跨会话找回

只写一个你真正在意的已读问题：

> 把这个问题记到《流浪地球》的阅读手账：【自己的问题】。只记这个问题，不改我的阅读进度。

保存后刷新或普通新建会话：

> 帮我找回刚才保存到《流浪地球》手账的那个问题。我想继续聊，不要替我修改。

预期：能够找回同一条用户问题及有记录时的阅读锚点；不把预测／感受当作品事实，不用新建会话把进度清空。未确认进度时可以保存无锚点条目，不应为保存手账自动推进。

手账目前读法是最近条目／简单文本包含，不是语义向量搜索。含糊描述未找到时，应合理查看近期条目或询问，不虚构不存在的记忆。一次失败记录实际表达即可，不用你不断换关键词帮它凑成功。

### C2 手账修订与删除（仅针对新写的测试条目）

> 把刚才保存的那个问题改成：【确实想改成的新问题】。其他条目别动。

再查看是否只改了目标、保留了“原来如何想／现在如何改”的归属。内部旧版本与来源由开发侧验证，不要求UI展示全部版本。

若这只是验收条目、不想留下：

> 删除刚才那条手账问题，只删这一条。

预期：目标不清楚先确认，不能删其他条目；后续手账查询不再返回该条。删除手账不等于删除旧聊天、摘要或所有记忆，AI不能承诺全系统彻底忘记。

### C3 剧情外 Note 与持续交互约定

仅当你真认可这项约定时，可写：

> 请记住一个交互约定：讨论剧情时，先回应我关注的点，再给必要证据，不要先复述情节。

预期：通过显式 Note 抽取工具提炼非剧情约定；之后普通新会话仍遵守。刚才的作品预测／人物看法不应被写进同一类约定。

如果不想永久保留测试约定，跳过此项，或明确使用：

> 请记住一条只在本次会话生效的临时约定：这次回复尽量短，跨会话不要沿用。

预期：temporary仅创建会话注入，不会自动抹去原始记录；不是“今天到期”的自动定时机制。短回复本身不能证明它正确存成临时项，开发侧需核对类别和来源。

如需取消新增约定，明确指向刚写的一条：

> 请删除刚才新增的那条【约定内容】Note，其他约定不要动。

Note停用不等于旧聊天或摘要被物理擦除；同一会话仍看得到你原来的指令，不能仅凭它还按旧指令说话判删除失败。停用后的新会话有效注入由开发侧核验。

### C4 同会话承接 vs 按日经历回忆（不混淆）

- 同会话问“我们刚才到底在纠结什么”，主要检验近期历史／checkpoint承接，不是跨会话语义搜索。
- C1保存的手账是显式稳定记录，跨会话应能查到，不依赖等到压缩。
- 新会话找回未显式保存的互动，需要那段讨论已经经过归档压缩和低频经历抽取。未触发时没有日经历，不等于原始对话被删除。
- 因此本轮不要刻意发送大量废话触发压缩，也不要把新会话找不到任意旧聊都记成失败。完整“压缩→抽取→新会话回忆”已有合成隔离验证；自然调度、多条真实经历和难负例仍由开发侧另验。
- 当开发侧确认某段经历已入库后，再用自己的新说法提问，例如“之前我为什么会对那个转折不满意？”；检验是否找回关注点、纠正和未解问题，而不是搜剧情事实来替代你的经历。

## 6. D：设置文档与可用性（可选，约3分钟）

- 打开“人格与规则”等设置入口，检查 SOUL.md、AGENTS.md、USER.md 三份文档是否都可查看，内容区域是否正常显示；不为验收编辑真实人格或用户信息。
- 检查“阅读原文”等按钮与页面其他控件不重叠，双栏时输入框仍可使用。
- 可切一次普通新会话再回来，确认历史能恢复。服务停止／重启、文件损坏和跨身份隔离由开发侧做，不要求你关闭后台或扮演其他用户。
- 不截图或公开含个人资料的 USER、Note、完整聊天、密码配置。缺少专门手账或经历管理页面是当前限制，不把尚未承诺的页面当成按钮故障。

## 7. 反馈方式：不用写长报告

每个问题记四件事即可，直接发在开发聊天：

> 用例：B2。我的意图：想讨论铺垫是否自然。实际：它继续解释人物动机。最没用的一句：【一句具体回复】。希望：沿着我的修正比较前后铺垫，不替作品圆。

可选结论：有帮助／能用但别扭／没有帮助／功能失败／待核验。若涉及引用、位置或存储，补上聊天名称、约略时间、已读位置；技术ID、完整工具日志由开发侧定位。

你可以明确说“这一条满意”，开发侧才将该项标为经过用户核验。未反馈、未做或没有报错不算通过。真实聊天默认保持本地私有，公开 result 只写脱敏现象、用例编号与修复／待办，不粘贴你的原文或完整对话；真实查询拿去算法实验另确认范围。

## 8. 第一阶段完成条件与分工

必须满足：

1. 网页阅读、选文和聊天没有阻断使用的故障。
2. 进度只在确认后写入；滚动、含糊定位、取消不推进；回答与工具材料不越已读边界。发生剧透／擅自推进立即阻断收口。
3. 至少一条真实连续讨论获用户认可：第一回复抓点、有理解增量、后续承接修正；不同解读不自动判错。
4. 至少一次显式手账保存与跨会话找回、一次真实非剧情Note生命周期完成；可分批做，不要求把测试约定永久留下。
5. 开发侧确认压缩／抽取／回忆、原始历史保留、owner／作品／边界隔离、工具失败兜底和重启恢复的受影响程序测试；已有合成模型验证的范围与未覆盖项明确记录，不宣称替代真实文学理解。

分工：用户判断真实帮助和自然承接；应用线核对工具调用、持久化、权限与上下文，按反馈修复阻断项；检索线研究来源可达性、完整证据、装包与排序成本，不直接用材料覆盖成绩宣称陪读满意。

不阻塞第一阶段的独立后续：更大检索集／跨作品留出、更多Embedding比较、ANN、框架迁移／多智能体、手机适配、完整记忆管理UI、MEMORY.md、跨层隐私彻底删除、复杂时间冲突处理。它们作为限制／TODO保留，不因暂缓而宣称已完成。

从当前状态估计，应用验收准备与阻断问题收口约4～8个有效开发小时；实际取决于真人反馈，若出现核心理解或安全缺陷重新估计。不是承诺所有后续算法与长期记忆研究在这个时间内完成。
