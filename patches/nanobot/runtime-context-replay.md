# 临时运行时上下文的历史回放

固定上游：`9ecdc4533f935bfd7cae9b8cbe651e77eec07cd7`。在已有六组 StoryPal 补丁之后应用 `storypal-runtime-context-replay.patch`。

## 为什么需要补丁

原 SDK 能追加来源块并持久化，但没有选择性退出历史回放的接口。每轮自动带入故事快照时，旧快照会反复进入模型。统一关闭运行时上下文会同时影响 Note、阅读状态和引用；删掉原始历史又会破坏溯源。因此增加通用 `RuntimeContextBlock(..., replay=False)`，不硬编码 StoryPal 名称。

## 行为

- 默认 `replay=True`，保持旧提供器、历史标记和 SDK 调用兼容。
- 当前轮仍完整注入；原始 JSONL 仍保存内容与来源。历史读取时，只移除经持久标记精确匹配的退出回放块；不按字符串全局替换，不删用户原话或工具观察。
- 文本、多模态、连续用户消息合并都保存逐块策略；用户侧历史仍沿用既有隐藏元数据行为。
- Codex 可恢复私有 Responses 状态，里面可能已经含旧视图。如果历史中有需移除的块，跨轮弃用该私有状态，从过滤后的本地历史重新组装。本轮内部的工具循环仍可继续使用新状态。仅有常驻块的会话不受影响。
- 这是上下文回放策略，不是沙箱、语义防剧透证明或 Prompt Injection 的完整防御。原历史保留，也不清理此前已有工具证据／用户观点。

## 验证与运行

补丁已在真实固定 commit 加既有 loop 补丁的独立临时基线上 `apply --check`、实际应用并逐文件比较一致；不是只对有本地改动的参考工作区检查。四个文件为 runtime_context、session/manager、agent/runner、agent/loop。

回归见 `chatbot_tests/test_runtime_context_replay.py`；上游回归需隔离本地第三方工具入口，否则其 `test-model` 假模型会被应用的 Luna 白名单拒绝。隔离只作用于测试进程，不修改运行白名单。

Python 后端补丁需重启 gateway；无需重建前端、重新初始化配置或覆盖人格文件。它改变私有响应状态恢复，可能影响缓存收益；真实模型延迟、缓存比例和压缩后的理解质量仍待连续链评测。
